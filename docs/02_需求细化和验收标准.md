## 2. MVP核心功能

### 2.1 MVP定义

**目标**: 2周内完成可运行的最小可用产品

**核心功能**:
1. 用户可以注册、登录
2. 用户可以创建一个AI角色
3. 用户可以与角色对话
4. 对话有基本的上下文记忆（5轮内）
5. 前端有基本的聊天界面

**不包含**:
- ❌ 长期记忆
- ❌ 上下文压缩
- ❌ 向量检索
- ❌ 流式响应
- ❌ 复杂的记忆系统

## 3. 详细功能需求

### 3.1 用户系统 (P0)

#### FR-U-001: 用户注册

**描述**: 用户可以通过邮箱和密码注册账号

**前置条件**: 无

**输入**:
- 用户名（3-20字符，字母数字下划线）
- 邮箱（有效格式）
- 密码（8-32字符，至少包含字母和数字）

**处理逻辑**:
1. 验证输入格式
2. 检查邮箱/用户名是否已存在
3. 密码bcrypt加密（cost=10）
4. 创建用户记录
5. 返回用户信息（不含密码）

**输出**:
```json
{
  "user_id": "uuid",
  "username": "alice",
  "email": "alice@example.com",
  "created_at": "2025-11-04T10:00:00Z"
}
```

**验收标准**:
- ✅ 相同邮箱不能重复注册
- ✅ 密码在数据库中是加密的
- ✅ 密码强度不足时返回明确错误
- ✅ 注册成功后自动登录

**测试用例**: [见第5节](#tc-u-001)

---

#### FR-U-002: 用户登录

**描述**: 用户通过邮箱和密码登录，获取JWT Token

**输入**:
- 邮箱
- 密码

**处理逻辑**:
1. 查询用户记录
2. 验证密码
3. 生成JWT Token（有效期24小时）
4. 更新last_login_at
5. 返回Token和用户信息

**输出**:
```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "Bearer",
  "expires_in": 86400,
  "user": {
    "user_id": "uuid",
    "username": "alice"
  }
}
```

**验收标准**:
- ✅ 密码错误返回401
- ✅ 用户不存在返回404
- ✅ Token可以正确解析出user_id
- ✅ Token过期后需要重新登录

- ✅ title为空时，在前3轮对话后自动生成

---

#### FR-CH-002: 发送消息 (核心功能)

**描述**: 用户在会话中发送消息，AI回复

**接口**:
```
POST /api/v1/conversations/{id}/messages
```

**输入**:
```json
{
  "content": "你好，我想问一个关于Python的问题"
}
```

**处理流程**:
```
1. 保存用户消息到数据库
2. 从Redis加载临时上下文（最近10条消息）
3. 检查Token数，判断是否需要压缩 (P1功能)
4. 调用Memory Service检索相关长期记忆 (P1功能)
5. 组装gRPC请求，调用LLM Service
6. 保存AI回复到数据库
7. 更新Redis临时上下文
8. 异步：提取关键信息，存入长期记忆 (P1功能)
9. 返回AI回复
```

**输出**:
```json
{
  "message_id": "uuid",
  "role": "assistant",
  "content": "你好！我很乐意帮助你解答Python相关的问题...",
  "created_at": "2025-11-04T10:05:00Z",
  "token_count": 150,
  "metadata": {
    "model": "gpt-4",
    "latency_ms": 1200
  }
}
```

**验收标准**:
- ✅ 响应时间P95 < 3秒
- ✅ AI回复符合角色设定
- ✅ 对话有上下文记忆（至少记住前5轮）
- ✅ Token使用被正确统计
- ✅ 成本被记录到llm_api_calls表

**错误处理**:
- LLM API调用失败：返回友好错误信息，不存储失败的消息
- 超时：30秒超时，提示用户重试
- 余额不足：提示用户充值或降低使用频率

### 3.4 记忆系统

#### FR-M-001: 临时记忆 (P0 - Redis)

**描述**: 当前对话的短期上下文，存储在Redis

**数据结构**:
```python
# Key格式
conversation:{conversation_id}:context

# Value (JSON)
{
  "messages": [
    {"role": "user", "content": "...", "timestamp": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "token_count": 3500,
  "last_compression_at": "2025-11-04T10:00:00Z"
}

# TTL: 24小时
```

**验收标准**:
- ✅ 保留最近10-20条消息
- ✅ 24小时未活动自动清理
- ✅ Token数准确计算

---

#### FR-M-002: 长期记忆存储 (P1)

**描述**: 将对话中的重要信息提取并存储

**触发时机**:
- 对话结束（用户离开）
- 检测到关键信息（LLM判断）
- 上下文压缩时

**提取内容**:
1. **用户画像更新**
   - 新发现的兴趣点
   - 用户的偏好变化
   - 专业背景信息

2. **关键事件**
   - 重要的决策
   - 情感转折点
   - 达成的共识

3. **关系变化**
   - 亲密度增加/减少
   - 信任度变化

4. **情感状态**
   - 用户当前情绪
   - 情绪变化趋势

**验收标准**:
- ✅ 每条记忆都有embedding向量
- ✅ 重要性评分准确（1-10）
- ✅ 记忆类型正确分类
- ✅ structured_data格式正确

---

#### FR-M-003: 记忆检索 (P1)

**描述**: 根据当前对话内容，检索相关的长期记忆

**检索策略**:
```python
# 混合检索
score = (
    vector_similarity * 0.5 +     # 向量相似度
    time_decay_weight * 0.3 +     # 时间衰减
    importance_score * 0.2        # 重要性
)
```

**参数**:
- 检索数量：5条
- 最小相似度：0.7
- 时间衰减半衰期：30天

**验收标准**:
- ✅ 检索延迟 < 200ms
- ✅ 返回的记忆与当前话题相关
- ✅ 时间越近的记忆权重越高
- ✅ 重要记忆优先返回

**测试场景**:
```
场景1: 用户说"我最近在学Python"
  → 应该检索到之前讨论Python的记忆

场景2: 用户说"还记得我上次说的那个项目吗"
  → 应该检索到相关项目的记忆

场景3: 30天前的记忆 vs 3天前的记忆
  → 内容相同时，3天前的应该排序更高
```

#### FR-M-004: 上下文压缩 (P1)

**描述**: 当临时上下文超过Token限制时，自动压缩

**触发条件**:
```python
current_tokens = count_tokens(temp_context)
threshold = model_max_tokens * 0.8  # 例如: 8000 * 0.8 = 6400

if current_tokens >= threshold:
    compress()
```

**压缩流程**:
```
1. 调用LLM生成摘要
   Prompt: "总结以下对话的核心内容，保留关键信息点..."

2. 提取关键点
   - 用户问的核心问题
   - AI给出的重要建议
   - 达成的结论

3. 提取记忆
   - 识别需要长期记住的信息
   - 生成embedding
   - 保存到long_term_memories表

4. 更新临时上下文
   - 清空旧消息
   - 保留最近3条消息
   - 插入摘要作为系统消息

5. 记录压缩历史
   - 保存到context_compressions表
```

**验收标准**:
- ✅ 压缩后Token数 < 原数量的30%
- ✅ 摘要包含核心信息，不丢失关键内容
- ✅ 压缩后对话仍然连贯
- ✅ 用户无感知（自动进行）

**测试用例**:
```
输入: 20轮对话，共8000 tokens
预期输出:
  - 摘要: 300 tokens
  - 保留最近3轮: 500 tokens
  - 总计: 800 tokens
  - 压缩率: 90%
```

#### FR-M-005: 关系图谱 (P2)

**描述**: 追踪用户与角色之间的关系变化

**维度**:
```json
{
  "relation_type": "friend",
  "closeness": 75,        // 0-100
  "emotional_bond": {
    "trust": 80,
    "affection": 70,
    "respect": 85
  },
  "interaction_count": 150,
  "total_conversation_time": 7200  // 秒
}
```

**更新策略**:
```python
# 每次对话后更新
def update_closeness(interaction_quality: float):
    # 基础增长
    increment = 1.0 * interaction_quality  # 0-1

    # 时间衰减（长时间不互动会降低）
    days_since_last = (now - last_interaction).days
    decay = exp(-days_since_last / 7)  # 7天半衰期

    # 新亲密度
    new_closeness = min(100,
        old_closeness * decay + increment
    )
```

**验收标准**:
- ✅ 频繁互动的角色closeness上升
- ✅ 长时间不互动closeness下降
- ✅ 互动质量影响增长速度
- ✅ closeness影响AI的回复风格

## 4. 非功能性需求

### 4.1 性能需求

| 指标 | 目标值 | 测量方式 |
