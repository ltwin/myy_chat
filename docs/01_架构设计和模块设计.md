## 1. 系统概述

### 1.1 项目背景
- **类型**: 个人项目 + 学习目的
- **规模**: 预期100-1000用户
- **核心价值**: 学习微服务架构、LLM应用开发、复杂记忆系统设计

### 1.2 核心功能
- ✅ 多角色管理（用户可创建/使用多个AI角色）
- ✅ 分层记忆系统（临时/长期/核心设定三层）
- ✅ 上下文压缩（防止Token溢出）
- ✅ 智能记忆检索（向量+时间衰减+重要性加权）
- ✅ OpenAI标准API兼容
- ✅ 实时对话（WebSocket + 流式响应）

### 1.3 非功能性需求
- **性能**: 对话响应时间 < 3秒（95th percentile）
- **可用性**: 99%正常运行时间
- **扩展性**: 支持水平扩展到1000+ QPS
- **可维护性**: 模块化设计、完善的日志和监控

```go
// 对话处理流程
func (s *ChatService) Chat(ctx context.Context, req *ChatRequest) (*ChatResponse, error) {
    // 1. 加载临时上下文（Redis）
    tempContext := s.loadTempContext(req.ConversationID)

    // 2. 检查是否需要压缩
    if tempContext.TokenCount > s.compressionThreshold {
        compressed := s.llmClient.CompressContext(ctx, tempContext)
        // 保存压缩摘要到长期记忆
        s.memoryService.SaveCompression(ctx, compressed)
        tempContext = compressed.Summary
    }

    // 3. 检索相关长期记忆
    memories := s.memoryService.RetrieveMemories(ctx, &RetrieveRequest{
        UserID:      req.UserID,
        CharacterID: req.CharacterID,
        Query:       req.Message,
    })

    // 4. 调用LLM服务生成回复
    llmResp := s.llmClient.Chat(ctx, &LLMChatRequest{
        UserMessage:       req.Message,
        MessageHistory:    tempContext.Messages,
        RelevantMemories:  memories,
        CharacterSettings: s.getCharacterSettings(req.CharacterID),
    })

    // 5. 保存消息到数据库
    s.saveMessages(ctx, req.ConversationID, req.Message, llmResp.Response)

    // 6. 更新临时上下文（Redis）
    s.updateTempContext(req.ConversationID, req.Message, llmResp.Response)

    // 7. 异步处理：提取关键信息并存储到长期记忆
    go s.extractAndSaveMemories(ctx, llmResp.KeyInfo)

    return llmResp, nil
}
```

**a. 对话编排 (Chat Service)**

```python
class ChatService:
    """对话编排服务"""

    async def chat(self, request: ChatRequest) -> ChatResponse:
        """处理对话请求"""
        # 1. 构建系统提示词
        system_prompt = self._build_system_prompt(
            character_settings=request.character_settings,
            memories=request.relevant_memories
        )

        # 2. 构建消息列表
        messages = self._build_messages(
            system_prompt=system_prompt,
            history=request.message_history,
            user_message=request.user_message
        )

        # 3. 调用LLM
        response = await self.llm_client.chat_completion(
            messages=messages,
            **request.generation_config
        )

        # 4. 提取关键信息（并行处理）
        key_info, sentiment = await asyncio.gather(
            self.extraction_service.extract_key_info(messages, response),
            self.sentiment_service.analyze(response)
        )

        return ChatResponse(
            response=response,
            key_info=key_info,
            sentiment=sentiment,
            token_usage=...
        )
```

**b. 上下文压缩 (Compression Service)**

```python
class CompressionService:
    """上下文压缩服务"""

    async def compress(self, request: CompressContextRequest) -> CompressContextResponse:
        """压缩对话上下文"""

        if request.compression_strategy == "summary":
            # 策略1: 总结摘要
            summary = await self._summarize(request.messages)

        elif request.compression_strategy == "key_points":
            # 策略2: 提取关键点
            key_points = await self._extract_key_points(request.messages)

        else:  # hybrid
            # 策略3: 混合（推荐）
            summary, key_points = await asyncio.gather(
                self._summarize(request.messages),
                self._extract_key_points(request.messages)
            )

        # 提取需要存入长期记忆的信息
        memories = await self._extract_memories_from_context(request.messages)

        return CompressContextResponse(
            summary=summary,
            key_points=key_points,
            extracted_memories=memories,
            compression_ratio=...
        )
```

**c. 记忆检索 (Memory Retrieval)**

```python
class MemoryRetrievalService:
    """记忆检索服务"""

    async def retrieve(self, request: RetrieveMemoriesRequest) -> List[Memory]:
        """检索相关记忆"""

        # 1. 生成查询embedding
        query_embedding = await self.embedding_client.embed(request.query)

        # 2. 向量检索（调用PostgreSQL函数）
        memories = await self.db.fetch("""
            SELECT * FROM search_memories_with_decay(
                $1::uuid,           -- user_id
                $2::uuid,           -- character_id
                $3::vector(1536),   -- query_embedding
                $4::integer,        -- limit
                $5::integer         -- decay_days
            )
            WHERE similarity > $6   -- min_similarity
        """, request.user_id, request.character_id, query_embedding,
            request.limit, 30, request.min_similarity)

        return memories
```

## 6. 核心功能设计

### 6.1 上下文压缩策略

**触发条件**:
```python
current_tokens = count_tokens(temp_context)
threshold = model_context_window * 0.8  # 80%阈值

if current_tokens >= threshold:
    trigger_compression()
```

**压缩流程**:
```
1. 识别关键消息
   - 用户的问题
   - 系统的关键回答
   - 包含重要信息的消息

2. LLM总结
   Prompt: "请总结以下对话的核心内容，保留关键信息点..."

3. 提取结构化信息
   - 用户意图
   - 讨论的主题
   - 达成的结论
   - 情感变化

4. 存储到长期记忆
   - 生成embedding
   - 评估重要性
   - 保存到数据库

5. 清理临时上下文
   - 保留最近N条消息
   - 保留压缩摘要
   - 更新Token计数
```

### 6.2 记忆检索策略

**混合检索算法**:
```python
def retrieve_memories(query: str, user_id: str, character_id: str, limit: int = 5):
    # 1. 向量相似度检索
    query_embedding = get_embedding(query)
    vector_results = vector_search(query_embedding, limit * 2)

    # 2. 应用时间衰减
    for memory in vector_results:
        days_ago = (now - memory.created_at).days
        time_weight = exp(-days_ago / 30)  # 30天半衰期

        # 3. 综合评分
        memory.score = (
            memory.similarity * 0.5 +      # 相似度权重50%
            time_weight * 0.3 +            # 时间权重30%
            (memory.importance / 10) * 0.2 # 重要性权重20%
        )

    # 4. 重排序并去重
    return deduplicate(sorted(vector_results, key=lambda x: x.score)[:limit])
```

### 6.4 关系图谱维护

**亲密度计算**:
```python
def update_closeness(user_id: str, character_id: str, interaction_quality: float):
    relationship = get_relationship(user_id, character_id)

    # 基础增长
    base_increment = 1.0

    # 质量调节
    quality_multiplier = interaction_quality  # 0.0 - 1.0

    # 衰减因子（长时间不互动会降低）
    days_since_last = (now - relationship.updated_at).days
    decay_factor = exp(-days_since_last / 7)  # 7天半衰期

    # 新亲密度
    new_closeness = min(100,
        relationship.closeness * decay_factor +
        base_increment * quality_multiplier
    )

    update_relationship(user_id, character_id, new_closeness)
```

## 10. 关键设计决策

### 10.1 为什么选择Golang + Python混合架构？

**决策**: 不采用纯Python或纯Golang，而是分层

**理由**:
1. **性能需求**: Golang处理高并发HTTP请求、WebSocket连接
2. **生态成熟度**: Python的LLM生态（LangChain）远超其他语言
3. **学习目标**: 掌握微服务、跨语言RPC通信

**代价**: 增加了运维复杂度，需要维护两套语言环境

---

### 10.2 为什么选择pgvector而不是专用向量数据库？

**备选方案**: Pinecone、Milvus、Qdrant

**决策**: 使用PostgreSQL + pgvector

**理由**:
1. **数据一致性**: 关系数据和向量数据在同一数据库，ACID保证
2. **运维简化**: 不需要额外维护向量数据库
3. **成本**: 开源免费，100-1000用户规模足够
4. **查询灵活**: 可以结合SQL做复杂过滤

**适用规模**: 向量数量 < 100万，QPS < 1000

---

### 10.3 为什么临时记忆用Redis而不是内存？

**决策**: Redis而非进程内存

**理由**:
1. **多实例共享**: 服务水平扩展时，所有实例共享上下文
2. **持久化**: 重启不丢失
3. **过期策略**: TTL自动清理

---

### 10.4 为什么需要Kafka？

**决策**: 引入消息队列（可选）

**使用场景**:
- 异步记忆存储（embedding生成耗时）
- 异步数据分析（成本统计）
- 事件驱动架构

**权衡**: 如果用户规模 < 500，可以先不引入，用Golang的channel处理
